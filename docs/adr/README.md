# Architecture Decision Records

ADRs capture important technical decisions, the context behind them, and the consequences we accept.

Use an ADR when a decision affects architecture, data models, APIs, infrastructure, security, or long-term maintainability.

ADRs should be marked as proposed, accepted, superseded, or deprecated.

Name ADRs with a sequential number and short kebab-case title:

```text
0001-use-postgres-for-primary-storage.md
```
