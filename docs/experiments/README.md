# Experiments

Experiments capture technical or product questions we need to answer before making a larger decision.

Use an experiment when we need evidence about feasibility, accuracy, performance, usability, cost, etc.

Name experiments with a sequential number and short kebab-case title:

Experiments should be marked as proposed, running, concluded, or archived.

If an experiment leads to an architectural decision, capture that decision in an ADR and link back to the experiment.
